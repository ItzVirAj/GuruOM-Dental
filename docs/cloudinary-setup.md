# Cloudinary Media Storage Setup Guide

This document describes the manual configuration steps required for the GuruOm Dental Cloudinary integration.

---

## 1. Create Account & Enable Two-Factor Authentication (2FA)
1. Sign up for a Cloudinary account at [https://cloudinary.com](https://cloudinary.com).
2. Go to **Settings** > **Account** > **Security**.
3. Enable **Two-Factor Authentication (2FA)** using your authenticator application.

---

## 2. Security Configuration (Strictly Server-Only Uploads)

### A. Confirm No Unsigned Upload Presets Exist
1. Navigate to **Settings** > **Upload** > **Upload presets**.
2. Review the list of presets.
3. Ensure **NO** preset has **Signing Mode** set to `Unsigned`.
4. If an `Unsigned` preset exists, delete or disable it immediately.
5. All uploads in GuruOm Dental are signed server-side through our authenticated endpoint (`POST /ow/api/media/upload`) using Cloudinary's Node SDK. The browser never receives Cloudinary API secrets.

### B. Enable Strict Transformations
To prevent cache-busting, unauthorized manipulation, or DDoS by transformation spamming, enable **Strict Transformations**:
1. Navigate to **Settings** > **Security** > **Strict Transformations**.
2. Toggle **Strict Transformations** to **Enabled**.
3. Under **Allowed Transformations**, enter the exact transformation strings generated by the application loader (`src/lib/media/cloudinary-loader.ts`):

```text
f_auto,q_auto,c_limit,w_320
f_auto,q_auto,c_limit,w_640
f_auto,q_auto,c_limit,w_960
f_auto,q_auto,c_limit,w_1280
f_auto,q_auto,c_limit,w_1920
f_auto,q_auto,c_limit,w_2400
c_fill,g_auto,w_1200,h_750
c_fill,g_auto,w_1200,h_630
c_fill,g_auto,w_300,h_300
```

4. Click **Save Changes**. Requests for any other transformation strings will be rejected with HTTP 404 by the Cloudinary CDN.

### C. Restrict Allowed Media Types
1. Go to **Settings** > **Security**.
2. Set **Allowed Media Types** to **Image** only (videos will be addressed in a future update).
3. Ensure delivery of PDF, SVG, and HTML files is restricted or disallowed.

---

## 3. Retrieve API Credentials & Configure Environment

1. Navigate to your **Cloudinary Dashboard**.
2. Under **Product Environment Credentials**, copy:
   - **Cloud name**
   - **API Key**
   - **API Secret**
3. Open `.env.local` in the project root and add the values:

```env
# Cloudinary Configuration
NEXT_PUBLIC_CLOUDINARY_CLOUD_NAME="your-cloud-name"
CLOUDINARY_CLOUD_NAME="your-cloud-name"
CLOUDINARY_API_KEY="your-api-key"
CLOUDINARY_API_SECRET="your-api-secret"

# Development folder separation (defaults to 'guruom-dev' in dev, 'guruom' in prod)
CLOUDINARY_FOLDER="guruom-dev"

# Upload and storage quotas
UPLOAD_MAX_BYTES=4194304
MEDIA_LIBRARY_MAX_BYTES=314572800
DAILY_UPLOAD_LIMIT=200
```

> **Security Rule:** `CLOUDINARY_API_KEY` and `CLOUDINARY_API_SECRET` must **NEVER** have a `NEXT_PUBLIC_` prefix and must never be imported in client components. The automated script `npm run check:leaks` enforces this guard.

---

## 4. Folder Separation Strategy
The application manages assets by environment folder:
* **Development / Staging:** `guruom-dev/YYYY-MM/`
* **Production:** `guruom/YYYY-MM/`

The folder is configured via the `CLOUDINARY_FOLDER` variable (defaults automatically based on `NODE_ENV`). Assets are organized under monthly subdirectories with cryptographically random UUID public IDs.

---

## 5. Secret Leak Emergency Rotation Procedure
If `CLOUDINARY_API_SECRET` is ever suspected of being exposed or committed:
1. Immediately log in to the Cloudinary Console.
2. Go to **Settings** > **Access Keys**.
3. Generate a **New API Key and Secret**.
4. Update your production environment variables (e.g. Vercel Project Settings) with the new credentials.
5. Redeploy the application.
6. Once the new deployment is live, **Revoke** the old compromised key in the Cloudinary Console.

---

## 6. Cloudinary Free Plan Limits Reminder
Monitor your Cloudinary plan usage under **Dashboard** > **Usage**:
* **Monthly Credits:** The free tier includes 25 Monthly Credits (~25,000 transformations or 25 GB net storage / bandwidth).
* The application enforces a soft library limit (`MEDIA_LIBRARY_MAX_BYTES=314572800`, 300 MB) and daily rate limits (`DAILY_UPLOAD_LIMIT=200`) to remain well within free tier thresholds.
* Use `npm run media:orphans` periodically to identify and clean up unreferenced assets.
